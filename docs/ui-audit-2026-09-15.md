**対象:** RAGZ建築 現場AI（Next.js / Tailwind / shadcn/ui / Supabase）  
**日付:** 2026-09-15  
**方針:** コード変更なし — 調査・問題特定・優先順位付けのみ

---

## A. Executive Summary

| 重要度 | 件数 |
|--------|------|
| Critical | 4 |
| High | 10 |
| Medium | 10 |
| Low | 5 |
| デッドコード | 6 |

現場AIのUIは視覚的には完成度が高く、カードデザイン・ステータスバッジ・緑系カラーパレットは一貫している。しかし内部を見ると **3つの構造的問題** が見つかった。

1. **デザイントークンの形骸化** — `globals.css` にネイビー系トークンが定義されているが、実際のコンポーネントはすべてインラインスタイルでグリーン系の生hex値を持つ。CLAUDE.md仕様（Primary: #1e3a5f）と実装（#1B2F23等）が乖離している。トークンを変更しても画面は変わらない。

2. **モバイルでのプロジェクト内タブ切替が不可能** — タブ切替はサイドバーからの `genba:tab` CustomEvent 経由のみ実装されており、`lg` 未満ではサイドバーが非表示になる。モバイルのBottomNavはグローバルナビのみで、プロジェクト内タブへのアクセス手段がない。

3. **URLにタブ状態が反映されない** — サイドバークリックでURLは変わらず、ページリロード・ブラウザバック・URL共有でタブ位置が失われる。

## B. TOP 10 問題

### C-01 🔴 Critical — モバイルでプロジェクト内タブ切替が不可能

タブ切替は `genba:tab` CustomEvent 経由のみで、lg未満ではサイドバーが `hidden`。BottomNavはグローバルリンク3本のみでプロジェクトタブへのアクセス手段がない。スマホユーザーは見積・工程・請求書等のタブに移動できない。

```
components/shell/BottomNav.tsx — 3グローバルタブのみ
layout.tsx:17 hidden lg:flex
```

---

### C-02 🔴 Critical — タブ状態がURLに反映されない（リロード・共有で位置消失）

サイドバーの `dispatchTab()` はURLを更新しない。ページリロードで常に `defaultTab`（estimate固定）に戻る。`searchParams.tab` は存在するが、サイドバークリックでは書き換えられない。

```
Sidebar.tsx:273 dispatchTab — history.pushState 未使用
ProjectTabs.tsx:105 defaultTab
```

---

### C-03 🔴 Critical — デザイントークンが全コンポーネントで無視されている

`globals.css` に `--color-background-primary` 等が定義されているが、実装は全てインラインスタイルの生hex値（#1B2F23, #2B5E40, #6CB382 等）。CLAUDE.md の Primary #1e3a5f は一度も使われていない。トークンを変えても画面は変わらない。

```
全コンポーネント: style={{ background: '#1B2F23' }} 等 30+ 箇所
globals.css: --color-background-primary 未参照
```

---

### C-04 🔴 Critical — デスクトップで戻るボタンが二重表示

lg+ では Sidebar に「案件一覧に戻る」アイコンボタンがあり、ProjectHeader にも `href="/projects"` の戻るボタンがある。同一機能が2箇所に並列表示され、UIの主従が曖昧になる。

```
Sidebar.tsx:303 IconBtn(back) href="/projects"
ProjectHeader.tsx:35 a href="/projects"
```

---

### H-01 🟠 High — タッチターゲット 44px 未満のボタンが複数存在

新規案件ボタン `minHeight: 36`、モーダルのキャンセル・送信ボタン（パディング10pxのみ≈34px）、ProjectHeader の戻るボタン28px。CLAUDE.md の 44px ルール違反。

```
ProjectListClient.tsx:323 minHeight: 36
ProjectHeader.tsx:37 width:28 height:28
```

---

### H-02 🟠 High — Sidebar の activeTab は UI に反映されない（状態と表示の乖離）

Sidebar は `useState('estimate')` で activeTab を管理し、クリック時に `setActiveTab` と `dispatchEvent` を呼ぶ。しかしサイドバー外からのタブ変更（URL searchParams 等）は Sidebar の activeTab に反映されないため、サイドバーのハイライトが実際のタブとずれる可能性がある。

```
Sidebar.tsx:271 useState('estimate') — genba:tab イベントの受信なし
```

---

### H-03 🟠 High — STATUS_CONFIG と導出バッジロジックが2ファイルに重複定義

`projects/page.tsx` と `projects/[id]/page.tsx` が同一の STATUS_CONFIG オブジェクトと請求書ステータス導出ロジックをそれぞれ独立定義。一方を直してももう一方に反映されずバグを生む。

```
projects/page.tsx:10 / projects/[id]/page.tsx:7 — 完全重複
```

---

### H-04 🟠 High — ProjectTabs に TABS 定義とスタイルが存在するが UI に使われていない

`ProjectTabs.tsx` は `TABS` 配列と `s.tabBar`/`s.tabItem` スタイルを定義しているが、JSX 内で一切参照されていない。タブ切替はサイドバーイベント頼みで、ProjectTabs 自身はタブバーを描画していない。

```
ProjectTabs.tsx:86-92 TABS, :133-156 s.tabBar/s.tabItem — JSXで未使用
```

---

### H-05 🟠 High — schedule タブが PROJECT_TABS に存在するが TABS const には含まれていない

Sidebar の PROJECT_TABS に `schedule` エントリがあり、ProjectTabs も `tab === 'schedule'` を処理するが、ProjectTabs の TABS 配列には schedule が含まれていない。TABS const とサイドバー定義の二重管理で、追加漏れが発生している。

```
Sidebar.tsx:134 schedule タブ
ProjectTabs.tsx:86 TABS — schedule なし
```

---

### H-06 🟠 High — NewProjectModal にダークモード対応がない

モーダルは `background: '#fff'`、テキスト `#192C1F`、ボーダー `#C8D8CA` をハードコード。ダークモード環境では黒背景に白モーダルが浮いて視認性が著しく低下する。

```
ProjectListClient.tsx:140 background: '#fff'
```

## D. Design System 監査

| 仕様元 | 定義値 | 実装値 | 状態 |
|--------|--------|--------|------|
| CLAUDE.md Primary | `#1e3a5f` (Navy) | 未使用 | ❌ 未使用 |
| globals.css `--color-background-primary` | 定義あり | `#F3F7F4` に直書き | ❌ 形骸化 |
| Sidebar background | （tokens なし） | `linear-gradient(#1B2F23, #121D16)` | ⚠️ 独自定義 |
| Accent green | （tokens なし） | `#6CB382` | ✅ 一貫使用 |
| Card background | （tokens なし） | `#FFFFFF` / `#F3F7F4` | ✅ 一貫使用 |
| CLAUDE.md タッチ最小 44px | 44px | 36px（新規案件）, 28px（戻る） | ❌ 違反 |

**結論:** globals.css のトークンは現状「あるだけ」の状態。全コンポーネントがインラインスタイルでグリーン系パレットを独自定義しており、トークンへの移行は将来的な改善課題。ただしグリーン系パレット自体は各コンポーネント間で一貫しており、視覚的統一感は保たれている。

## Q. 最終質問 Q1–Q8

**Q1. モバイルのプロジェクト内タブナビはどう実装すべきか？**

選択肢は3つ。①BottomNavをコンテキスト対応にする（/projects/[id] にいるときだけプロジェクトタブを表示）— CLAUDE.md のモバイル設計に最も近い。②/projects/[id] ページ上部にスクロール可能なタブバーを追加 — PCではSidebarを使い続けられる。③スワイプジェスチャー対応 — 工数が高く優先度低。**推奨は②**で、Sidebarによるタブ切替をPC専用機能として残し、モバイルには独立タブバーを追加する。

**Q2. CLAUDE.md の Primary #1e3a5f（Navy）は使う予定があるか？**

現状は全コンポーネントがグリーン系パレットで統一されており視覚的一貫性は保たれている。Navy への移行を計画しないなら、CLAUDE.md の記述を現状の緑系パレットに更新し、globals.css の Navy トークンを削除するほうが混乱が少ない。

**Q3. タブ状態をURLに反映させる場合、`router.replace` か `router.push` か？**

**`router.replace` を推奨。** タブ切替は画面内の状態変化であり、ブラウザの「戻る」でタブが変わるのはユーザーにとって不自然。replaceならブラウザ履歴は増えず、リロード・共有でのURL永続化だけが得られる。

**Q4. BottomNav の3タブは CLAUDE.md の「2項目」と乖離しているが、これは意図的か？**

資材マスター機能が設計後に追加されたことで実質3タブになったと思われる。CLAUDE.md を更新して3タブを正式仕様とするか、資材マスターをサイドバー専用（PC のみ）とするかを決める必要がある。スマホユーザーが資材マスターを使う頻度によって判断する。

**Q5. Sidebar のステータスドット（緑ドット bottom）は何を表しているか？**

コードを見る限り意味のある状態変化に紐づいていない（常時緑のハードコード）。Supabase Realtime の接続状態を表示するなら state と連動させ、ラベルを付けるべき。装飾にすぎないなら削除して余白を整理したほうが潔い。

**Q6. EstimateImportTab.tsx / VendorInvoiceImportTab.tsx はどこから使われているか？**

ProjectTabs の TABS 定義にもサイドバー定義にも対応エントリがなく、参照元が確認できなかった。grep で実際のimport先を確認し、未使用なら削除候補。使われているなら、サイドバーに対応タブを追加してユーザーからアクセス可能にする必要がある。

**Q7. グローバル CustomEvent（genba:tab / genba:total / genba:open-chat）は今後も使い続けるか？**

現状は機能しているが、コンポーネント間の暗黙的な依存関係を生む。URL state（`router.replace`）に移行すれば `genba:tab` イベントバスを減らせる。`genba:total` は親コンポーネントへの props コールバックに置き換えるのが最も安全。

**Q8. ダークモード対応は必要か？**

Sidebar・BottomNavは意図的にダーク固定で問題ない。しかしカード・モーダル・ページ背景がライトハードコードのため、OSをダークモードに設定したユーザーには「暗いフレームの中に白いコンテンツ」という分裂したUIが表示される。工務店の実用ツールとしてダークモードのユーザーが少ないなら後回しでよいが、将来対応するなら H-06（NewProjectModal）から始め、globals.css トークンを活用する段階的移行が推奨。
