# 業者請求書 OCR（原本と読み取り結果の比較・税抜登録）の Browser QA

本番 DB・本物の AI には接続しない。`/qa/cost-ledger`（開発環境専用 Fixture）で行う。

1. `npm run dev:start`（PID を控える）→ `http://localhost:3000/qa/cost-ledger`
2. 上部の QA バーの「読み取り結果」で、次の AI 読み取りで返す架空の請求書を選ぶ
   （税抜10万・税1万・税込11万／税込11万のみ／内税／税率8%／8%・10%混在／消費税の記載なし／非課税／値引き・端数で合計が合わない／読み取り失敗）
3. 「業者請求書取り込み」→ 架空の請求書画像を選ぶ → 「請求書を読み取る」
4. 確認すること
   - PC（1024px 以上）: 左に原本・右に読み取り結果。右をスクロールしても原本が追従する。拡大・縮小ができる
   - スマートフォン: 原本が上、読み取り結果が下。横スクロールが出ない（パネル内）
   - 「原本の金額」の照合結果（整合OK / 要確認）と注意書きがシナリオどおり
   - 登録金額（税抜）: 税込しかない・読み取り失敗では空欄。税込から割り戻した値を入れない
   - 「税抜であることを原本で確認しました」にチェックするまで登録できない。登録金額を変えるとチェックが外れる
   - 支払期日は参考表示だけ。登録した内訳の支払日は空（`payment_date = null`）
   - 登録後: 「¥X（税抜）を原価台帳に登録しました」と実績累計が出る。台帳の業者請求額が増える
   - 連打しても 1 件だけ。「次の登録: 応答を失う」→ 再度押すと「前回の送信で登録済み」で増えない
   - 同じ画像をもう一度登録すると「この請求書は登録済みです」
   - 読み取り中に画像を変えると、古い読み取り結果は表示されない
   - 値引き・源泉徴収の記載がある請求書は、印字どうしが合っていても「要確認」。値引き・源泉徴収の行が「原本の金額」に表示される
   - 明細が 20 行を超える請求書は「原本は N 行。残りは原本で確認」と出る（登録金額には明細を使わない）
   - HEIC・PDF を選ぶと、対応していない理由と対処が出て読み取らない
   - 3.5MB を超える写真は送信前に縮小され、「送信用に画像を縮小しました（元 → 送信）」と出る。数字が読める画質か原本表示と見比べる
5. `performance.getEntriesByType('resource')` で supabase.co と `/api/` への実通信が 0 件であること
6. 終了時は `npm run dev:stop -- --pid <控えた PID>`

架空の請求書画像の例は、Fixture の業者名（QA設備）・請求書番号（QA-INV-001）に合わせて作る。実在の会社・顧客の請求書は使わない。
