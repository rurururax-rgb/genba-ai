# 見積書 OCR の実 AI 検証（架空の見積書）

本物の Claude API で `/api/ai/extract-estimate` を呼び、正解データと比べる。DB には接続しない（認証だけ模擬）。
画像はすべて架空（`scripts/ocr-live/make-estimates.mjs` がヘッドレス Chrome で作る）。実在の会社・顧客の情報を AI に送らないこと。

```bash
node scripts/ocr-live/make-estimates.mjs                 # 画像と正解 JSON を作り直す（任意）
OCR_ENV_FILE=<.env.local のパス> npx vitest run --config vitest.live.config.ts
OCR_CASES=case4-traps,case6-unit-only …                  # 一部のケースだけ（API 呼び出しは 1 ケース 1 回）
```

`OCR_ENV_FILE` からは `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` だけを読む。結果は `OCR_OUT`（既定は OS の一時フォルダ）に保存する。
通常の `npm test` には含まれない（費用がかかるため）。

## ケース

| ケース | 内容 | 見るところ |
|---|---|---|
| case1-rate | 定価・掛率・単価・数量・金額（10 行・小数の数量あり） | 列の取り違え |
| case2-discount | 出精値引あり（値引後の小計は印字なし） | 値引きを原価に入れない・警告 |
| case3-long65 | 明細 65 行を A4 1 枚に | 読み落とし・途中終了・出力トークン |
| case4-traps | 単価欄空（数量 3 / 数量 1）・業者の誤記・含む・0 円・別途 | 単価を作らない・要確認・除外行の案内 |
| case5-photo | case1 を傾け・ぼかし・縮小（スマホ撮影の模擬） | 画質が落ちたときの正確さ |
| case6-unit-only | 単価の列だけ（金額・定価なし） | 照合できないことの警告 |

失敗にする条件: 原本と違う単価・数量が「要確認」なしで通る（silent wrong）／除外すべき行が明細に入る／値引き・別途・照合不能の警告が出ない／
読み落としがあるのに警告が出ない。

正常に読み取れるべき代表ケース（上の 6 件・テストの `MUST_SUCCEED`）は、200 で原本の全行を読み、原本にない行を作らないことまで求める。
途中終了・タイムアウトなどのエラー（明細を返さず案内を出す）で終わった場合も**失敗**にする。
安全なエラー終了を許すのは、出力上限を超える大きさの見積書など `MUST_SUCCEED` に入れないケースだけ（途中終了の扱いは模擬 SDK の単体テストでも確認している）。
